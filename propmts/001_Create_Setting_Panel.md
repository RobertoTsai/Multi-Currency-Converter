/speckit.specify

請為現有 Chrome 擴充功能「Multi-Currency Converter Extension」新增「設定」功能。

本專案是棕地專案，所有與擴充功能本體相關的新增與修改，皆必須位於 `Extension/` 目錄下。請保留既有 popup、貨幣換算、拖曳排序、快取、多語系與使用者設定行為，不得破壞既有功能。

## 功能目標

在擴充功能 popup 中新增一個「設定」按鈕。使用者點擊後，可以開啟設定畫面，並設定數字顯示格式與介面語言。

此功能的目標是讓使用者能自訂貨幣金額的顯示格式，包括小數點符號、千分位分隔符，以及語言設定，並能即時看到格式預覽。

## 使用者故事

作為使用者，我希望可以在擴充功能中開啟設定畫面，選擇我偏好的小數點與千分位格式，並設定介面語言，讓貨幣金額以我熟悉的格式顯示。

## 需求範圍

### 1. 設定按鈕

- 在現有 popup 介面中新增一個「設定」按鈕。
- 設定按鈕應符合既有 UI 風格與深色主題。
- 點擊設定按鈕後，應開啟設定畫面。
- 設定畫面可以是 modal、內嵌面板或替換式畫面，但必須維持 popup 尺寸限制與操作流暢性。
- 設定畫面必須提供返回或關閉方式，讓使用者能回到主要貨幣換算畫面。

### 2. 小數點格式設定

使用者可以選擇小數點符號：

- `.`
- `,`

此設定會影響貨幣金額的顯示格式。

### 3. 千分位設定

使用者可以選擇千分位分隔方式：

- 無
- 空格
- `.`
- `,`

此設定會影響貨幣金額的顯示格式。

### 4. 格式衝突處理

當小數點格式與千分位設定相同時，系統必須避免產生不可讀或有歧義的格式。

請在規格中定義清楚的處理方式，例如：

- 禁止選擇相同符號組合；或
- 自動調整另一個設定；或
- 顯示錯誤提示並不保存；或
- 允許但明確說明顯示結果。

請優先選擇能避免使用者困惑的方案。

### 5. 設定預覽

設定畫面下方必須顯示格式預覽。

預覽應使用固定範例數字：

- 原始數值：`12345.67`

預覽範例應依使用者目前選擇即時更新。

例如：

- 小數點為 `.`，千分位為 `,` 時，顯示 `12,345.67`
- 小數點為 `,`，千分位為 `.` 時，顯示 `12.345,67`
- 小數點為 `.`，千分位為空格時，顯示 `12 345.67`
- 小數點為 `,`，千分位為無時，顯示 `12345,67`

### 6. 語言設定

設定畫面需提供語言設定。

- 若使用者從未設定過語言，預設值必須為 `English`。
- 語言設定應與既有多語系機制整合。
- 語言設定變更後，應影響擴充功能中使用者可見文字。
- 語言選項至少應包含既有支援的語言。
- 若目前程式已有 `userLanguage` 或類似 Chrome storage key，應優先相容既有儲存行為。
- 不得破壞既有依瀏覽器語言判斷的行為，除非規格明確定義新的優先順序。
- 請定義語言優先順序，例如：
  1. 使用者已明確設定的語言
  2. 若未設定，預設為 English

### 7. 設定保存

所有設定必須保存於 Chrome storage 中。

需保存的設定至少包含：

- 小數點格式
- 千分位分隔方式
- 語言設定

設定保存後，關閉並重新開啟 popup 時應維持使用者選擇。

若既有使用者沒有這些設定，應套用安全預設值：

- 小數點格式：`.`
- 千分位設定：`,`
- 語言設定：`English`

### 8. 對既有貨幣換算顯示的影響

新增設定後，主要貨幣清單中的金額顯示應套用使用者選擇的小數點與千分位格式。

此功能不應改變實際換算計算邏輯，只改變顯示格式。

使用者輸入金額時，請在規格中定義輸入格式的處理方式：

- 是否允許使用者輸入自訂小數點符號
- 是否允許千分位符號出現在輸入框
- 若輸入格式與設定不一致時如何處理
- 是否只在顯示時格式化，而輸入解析仍維持既有行為

請優先避免破壞既有輸入行為。

## 非目標

本次功能不包含：

- 新增新的匯率來源
- 修改匯率計算公式
- 修改快取時間
- 新增新的貨幣種類
- 大幅重設 popup UI
- 引入新的大型前端框架
- 新增分析、追蹤或遙測功能

## 棕地相容性要求

請明確描述以下事項：

- 必須保留既有預設貨幣列表。
- 必須保留既有使用者自訂貨幣列表。
- 必須保留既有拖曳排序行為。
- 必須保留既有刪除確認行為。
- 必須保留既有新增貨幣與搜尋貨幣行為。
- 必須保留既有匯率快取行為。
- 必須保留既有 popup-window 按鈕行為。
- 不得破壞 `currency_config.json` 的貨幣名稱、符號、圖示與多語系資料使用方式。

## UI 與可用性要求

- 設定畫面必須符合既有 `styles.css` 的視覺語言。
- 應優先使用既有 CSS custom properties。
- 設定項目需有清楚標籤。
- 預覽區需清楚標示，例如「預覽」或「Format Preview」。
- 設定變更應即時反映在預覽中。
- 設定畫面應有明確的關閉、返回或完成操作。
- 若設定會立即保存，需在規格中說明。
- 若需按下保存按鈕才保存，需在規格中說明。

## 在地化要求

所有新增使用者可見文字都必須加入既有多語系機制，不得只寫死單一語言。

新增文字至少需包含：

- English
- 繁體中文 zh-TW
- 簡體中文 zh-CN

可能需要新增的文字包含但不限於：

- 設定
- 小數點格式
- 千分位設定
- 無
- 空格
- 語言
- 預覽
- 儲存
- 取消
- 關閉
- 返回
- 格式設定錯誤提示

## 儲存與資料模型要求

請在規格中定義設定資料模型。

建議但不強制的資料欄位：

- `decimalSeparator`
- `thousandsSeparator`
- `userLanguage`

請說明：

- 儲存位置使用 `chrome.storage.sync` 或既有專案慣用的 Chrome storage。
- 缺少設定時的預設值。
- 既有 `userLanguage` 設定如何相容。
- 儲存資料異常或非法值時如何 fallback。
- 是否需要 migration；若需要，migration 必須具備冪等性。

## 驗收標準

請產出可測試的驗收標準，至少包含：

1. 使用者可在 popup 中看到設定按鈕。
2. 點擊設定按鈕後可開啟設定畫面。
3. 使用者可選擇小數點格式為 `.` 或 `,`。
4. 使用者可選擇千分位設定為無、空格、`.` 或 `,`。
5. 設定預覽會依目前選項即時更新。
6. 當小數點為 `.` 且千分位為 `,` 時，預覽顯示 `12,345.67`。
7. 當小數點為 `,` 且千分位為 `.` 時，預覽顯示 `12.345,67`。
8. 當小數點為 `.` 且千分位為空格時，預覽顯示 `12 345.67`。
9. 當小數點為 `,` 且千分位為無時，預覽顯示 `12345,67`。
10. 使用者從未設定語言時，語言預設為 English。
11. 使用者變更語言設定後，重新開啟 popup 仍保留該語言。
12. 使用者變更數字格式後，重新開啟 popup 仍保留該格式。
13. 主要貨幣清單的金額顯示會套用使用者選擇的格式。
14. 實際匯率計算結果不因顯示格式設定而改變。
15. 既有新增貨幣、刪除貨幣、搜尋貨幣、拖曳排序功能仍正常。
16. popup 開啟時無 console error。
17. 所有新增或修改的擴充功能執行檔案皆位於 `Extension/` 目錄。
18. 所有 Spec Kit 產出的規格與技術文件皆使用繁體中文 zh-TW。

## 邊界案例

請在規格中處理以下情境：

- 使用者選擇相同的小數點與千分位符號。
- Chrome storage 中沒有任何新設定。
- Chrome storage 中存在非法設定值。
- 使用者語言設定不存在。
- 使用者語言設定為目前不支援的語言代碼。
- 使用者在設定畫面開啟後直接關閉 popup。
- 匯率資料尚未載入完成時切換格式設定。
- 貨幣金額為 0、負數、大數、小數位很多的數字時如何顯示。
- 加密貨幣與法幣是否使用同一套格式規則。

## 人工驗證清單

請產出人工驗證清單，至少包含：

- 載入 `Extension/` 作為 unpacked extension。
- 開啟 popup 並確認既有貨幣清單正常顯示。
- 點擊設定按鈕並確認設定畫面開啟。
- 測試所有小數點與千分位組合。
- 確認預覽即時更新。
- 確認不允許或可妥善處理衝突格式。
- 修改語言後重新開啟 popup，確認設定保存。
- 修改數字格式後重新開啟 popup，確認設定保存。
- 確認主要貨幣金額顯示格式已更新。
- 確認匯率換算結果仍正確。
- 確認新增、刪除、搜尋、拖曳排序仍正常。
- 模擬缺少 storage 設定時確認使用預設值。
- 檢查 console 無非預期錯誤。
