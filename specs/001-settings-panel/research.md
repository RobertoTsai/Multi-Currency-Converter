# 技術研究與決策 (Technical Research & Decisions)

**功能分支**: `001-settings-panel`

本文件記錄了在實作「設定面板」功能時所作出的關鍵技術決策、評估方案以及最終採用的實作設計。

---

## 研究課題 1：多檢視切換設計 (View Navigation)

### 決策：雙容器 Display 切換 (Double-Container Display Toggle)

-   **做法**: 
    在 `popup.html` 中將現有的主換算區域（排除 header，或包含 header）封裝在 `<div id="main-view">` 中，並新增同層級的 `<div id="settings-view" style="display: none;">` 作為設定面板。點擊設定與返回按鈕時，透過 `popup.js` 控制兩個 div 的 `display` 屬性（`block` / `none`）。
-   **理由**: 
    -   不需要引入任何額外的 SPA 路由函式庫（符合憲法原生平台原則）。
    -   效能最優，切換時間低於 5ms，無白屏或 DOM 重新渲染延遲。
    -   popup 的寬高尺寸（380x480）在隱藏/顯示時能維持穩定，避免因 layout 重新排列造成視窗劇烈閃爍。
-   **評估的替代方案**:
    -   *方案 A: Modal 彈出視窗疊加*
        -   *缺點*: 由於 popup 寬度僅有 380px，如果在既有 UI 上方疊加 Modal，會顯得非常擁擠，且 modal 遮罩會讓背景的換算欄位無法閱讀，操作體驗較差。
    -   *方案 B: 動態加載 HTML 片段*
        -   *缺點*: 需要使用 `fetch` 載入新 html 或以 `innerHTML` 注入，增加額外網路開銷且容易在 Manifest V3 CSP 限制下產生安全性警告。

## 研究課題 2：數字格式化自訂 (Number Formatting)

### 決策：輕量級字串正則替換 (Regex-based String Formatting)

-   **做法**: 
    自訂 `formatCustomNumber(value, decimalSep, thousandsSep)` 函數。
    1.  將數值轉換為固定小數點數（例如 `toFixed(2)`）。
    2.  將其分割為整數部分和小數部分。
    3.  整數部分使用正則表達式 `\B(?=(\d{3})+(?!\d))` 配合指定千分位字元進行替換。
    4.  最後以指定的小數點字元將整數部分與小數部分連接起來。
-   **理由**: 
    -   JavaScript 內建的 `Intl.NumberFormat` 在處理某些非標準組合（例如小數點是逗號 `,` 且千分位是點 `.`）時，會強制依循特定語系（Locale）標準，不易實現任意符號的彈性組合。
    -   代碼量極小（低於 15 行），完全可控，且能完美處理加密貨幣的多位小數情況（小數部分不加千分位）。
-   **評估的替代方案**:
    -   *方案 A: 依據選定符號動態選用 Locale 呼叫 `Intl.NumberFormat`*
        -   *缺點*: 某些自訂組合（如千分位為空格、小數點為逗號）沒有對應的單一 Locale 可以 100% 吻合，會導致某些瀏覽器下渲染行為不一致。

## 研究課題 3：格式衝突預防 (Conflict Prevention)

### 決策：即時聯動更換 (Real-time Linked Swap)

-   **做法**: 
    在設定面板的 `change` 事件中監聽選項。當使用者將小數點設為 `A`，且千分位當前也是 `A` 時，系統自動將千分位改為 `B`（若 A 為 `.` 則 B 為 `,`，反之亦然）。此過程在 UI 上立即聯動變更並即時保存，並在預覽區顯示結果。
-   **理由**: 
    -   防呆設計最安全，避免使用者設定出例如 `12.345.67` 的無效格式。
    -   不需要顯示擾人的錯誤彈窗，提升操作流暢度。
-   **評估的替代方案**:
    -   *方案 A: 允許選擇相同，但在保存時報錯並不予保存*
        -   *缺點*: 由於我們採用即時保存（不設儲存按鈕），當使用者選擇衝突時，如果突然關閉 popup 會導致儲存的資料狀態處於灰色地帶，或讓預覽區顯示混亂。

## 研究課題 4：輸入解析與算式支援 (Input Parsing & Math Evaluation)

### 決策：輸入淨化與標準化轉換 (Input Sanitation & Normalization)

-   **做法**: 
    當使用者在金額欄位輸入時：
    1.  **輸入過濾**: 依據設定，僅允許輸入數字、運算符號 `+-*/()` 以及*當前設定的小數點符號*。
    2.  **算式解析**: 在 `parseFormattedNumber` 與 `evaluateExpression` 中，首先將輸入字串中的「千分位分隔符」（如果是點、空格或逗號）全部移除，再將「自訂小數點符號」（如果是逗號 `,`）替換為標準的點 `.`。
    3.  將標準化後的字串送入運算引擎計算，最後將計算出的標準 JavaScript float 傳遞給其他貨幣換算，並輸出對應的顯示格式。
-   **理由**: 
    -   既有的算式計算引擎（`evaluateExpression`）非常依賴標準 `.` 作為小數點與無千分位的格式。先進行格式標準化，可達到對既有換算引擎的零侵入（0 regression 門檻）。
-   **評估的替代方案**:
    -   *方案 A: 編輯時完全脫除格式，只在 Blur 時套用*
        -   *缺點*: 既有行為在輸入時（Input 事件）會即時以千分位格式化當前輸入框（`formatNumberWithCommas`），如果輸入時完全不格式化，會破壞原本「即時格式化輸入值」的視覺回饋。
