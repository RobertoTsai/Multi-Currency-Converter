# Feature Specification: 設定面板 (Settings Panel)

**Feature Branch**: `001-settings-panel`

**Created**: 2026-06-09

**Status**: Draft

**Input**: User description: 
```text
請為現有 Chrome 擴充功能「Multi-Currency Converter Extension」新增「設定」功能。
本專案是棕地專案，所有與擴充功能本體相關的新增與修改，皆必須位於 `Extension/` 目錄下。請保留既有 popup、貨幣換算、拖曳排序、快取、多語系與使用者設定行為，不得破壞既有功能。
在擴充功能 popup 中新增一個「設定」按鈕。使用者點擊後，可以開啟設定畫面，並設定數字顯示格式與介面語言。
此功能的目標是讓使用者能自訂貨幣金額的顯示格式，包括小數點符號、千分位分隔符，以及語言設定，並能即時看到格式預覽。
```

## 使用者情境與測試 (User Scenarios & Testing) *(mandatory)*

### 使用者故事 1 - 設定按鈕與介面切換 (Priority: P1)

使用者可以在主要換算畫面的角落清晰地看到「設定」按鈕（齒輪圖示），點擊後，主要貨幣清單與新增按鈕等主畫面內容隱藏，並以平滑的轉場效果顯示設定面板。使用者在設定面板中可以點擊「返回」按鈕以回到原本的貨幣換算主畫面，且原本輸入的金額與貨幣清單順序保持不變。

**為什麼是此優先級**: 這是設定功能的入口與基本框架，如果無法在主畫面與設定畫面之間切換，則後續所有自訂功能都無法被使用者觸及。

**獨立測試**: 可以透過點擊設定按鈕成功切換至設定畫面，且點擊返回按鈕能正確切換回主畫面，並驗證主畫面的既有資料（如最後輸入的金額、貨幣順序）均完好無損。

**驗收情境**:
1. **Given** 使用者處於主要換算畫面，**When** 點擊右上角的「設定」按鈕，**Then** 系統隱藏主要貨幣清單與下方按鈕，並在原 popup 視窗內渲染並顯示「設定面板」畫面。
2. **Given** 使用者處於設定面板畫面，**When** 點擊左上角的「返回」按鈕，**Then** 系統隱藏設定面板，重新顯示主要貨幣清單與原本的金額，且 console 中無任何 JavaScript 錯誤。

---

### 使用者故事 2 - 小數點與千分位格式自訂與即時預覽 (Priority: P1)

使用者可在設定面板中，透過下拉選單或單選按鈕分別選擇「小數點符號」與「千分位分隔符」。設定面板下方設有一個「格式預覽」區塊，顯示固定數值 `12345.67` 的格式化結果，該預覽在使用者切換選項時會立即更新。當使用者返回主畫面時，所有貨幣欄位的金額（包含輸入框的顯示值與其他欄位的換算值）皆會立即套用該格式。

**為什麼是此優先級**: 這是使用者自訂數字格式的核心需求，直接決定了使用者是否能以其熟悉的本土化格式閱讀貨幣金額。

**獨立測試**: 在設定面板中隨意切換小數點與千分位的組合，觀察預覽數值是否即時變更，並返回主畫面確認所有貨幣列的金額分隔符是否皆已變更為選定符號。

**驗收情境**:
1. **Given** 使用者在設定面板，**When** 選擇小數點為 `.` 且千分位為 `,`，**Then** 預覽區域立即渲染顯示 `12,345.67`。
2. **Given** 使用者在設定面板，**When** 選擇小數點為 `,` 且千分位為 `.`，**Then** 預覽區域立即渲染顯示 `12.345,67`。
3. **Given** 使用者在設定面板，**When** 選擇小數點為 `.` 且千分位為 `空格`，**Then** 預覽區域立即渲染顯示 `12 345.67`。
4. **Given** 使用者在設定面板，**When** 選擇小數點為 `,` 且千分位為 `無`，**Then** 預覽區域立即渲染顯示 `12345,67`。

---

### 使用者故事 3 - 格式衝突自動調整防呆 (Priority: P2)

為了避免使用者設定出相同的小數點與千分位符號（例如兩者皆為 `.` 或兩者皆為 `,`），導致金額數值產生可讀性歧義，系統必須提供防呆機制。當使用者選定某一選項時，若該選項與另一設定相同，系統應自動將另一設定變更為其他相異的預設符號，從根本上杜絕衝突格式。

**為什麼是此優先級**: 這是確保系統資料一致性與使用者體驗的必要防護措施，避免產生如 `12.345.67` 這種極易混淆的格式。

**獨立測試**: 在設定面板中，嘗試點選與當前另一選項相同的符號，驗證另一選項是否會自動跳轉為不衝突的選項。

**驗收情境**:
1. **Given** 當前設定為小數點 `.`、千分位 `,`，**When** 使用者將小數點改選為 `,`，**Then** 系統自動將千分位設定調整為 `.`（或 `無`/`空格`），以防止兩者皆為 `,`。
2. **Given** 當前設定為小數點 `,`、千分位 `.`，**When** 使用者將千分位改選為 `,`，**Then** 系統自動將小數點設定調整為 `.`，以防止兩者皆為 `,`。

---

### 使用者故事 4 - 介面語言變更與持久化 (Priority: P2)

使用者可以在設定面板中切換介面語言。切換後，擴充功能介面上的所有可見文本（包含按鈕、標籤、確認對話框提示、錯誤訊息等）將立即更新為選定語言。此設定與其他數字格式設定皆會立即儲存於 Chrome storage 中，確保在重新開啟擴充功能或瀏覽器重啟後，偏好設定依然存在。

**為什麼是此優先級**: 讓不同語言偏好的使用者能擁有完全本地化的操作體驗，且設定必須持久化才能算作完整的設定功能。

**獨立測試**: 在設定面板切換語言為「繁體中文」，檢查介面是否即時更新為繁體中文。關閉 popup 並重新開啟，確認介面語言依然是繁體中文。

**驗收情境**:
1. **Given** 系統預設語言為英文，**When** 使用者在語言選單中選擇 `繁體中文`，**Then** 介面所有文字（包括設定選單、確認對話框）立即翻譯為繁體中文。
2. **Given** 使用者已將語言設定為 `繁體中文`，小數點設定為 `,`，**When** 關閉 popup 並重新開啟，**Then** 設定畫面與主要換算畫面均載入並套用上述設定。

---

### 邊界案例 (Edge Cases)

- **Chrome Storage 中無任何新設定（新安裝或首次升級）**:
  系統必須套用安全預設值：小數點為 `.`，千分位為 `,`，語言設定為 `English`（若未設定語言，亦可依既有邏輯偵測瀏覽器語言，並在偵測為中文時 fallback 至 `zh-TW` 或 `zh-CN`，其他則預設為 `en`）。
- **Chrome Storage 中存在非法或損壞的數值**:
  如果讀取到的 `decimalSeparator` 或 `thousandsSeparator` 包含不支援的字元或值，系統必須靜默 fallback 到預設值（`.` 與 `,`），不拋出 JavaScript 錯誤，不影響 popup 的開啟。
- **使用者在設定畫面開啟時直接關閉 popup**:
  由於本功能將採用「即時變更即時存入 Storage」的策略（無須點擊儲存按鈕），當使用者直接關閉 popup，當前已選取的設定仍應成功保存。
- **加密貨幣小數點位數多且數值極小 (e.g. 0.00001234)**:
  千分位分隔符僅套用於整數部分。小數部分（無論幾位）必須只使用使用者設定的小數點符號，其內部數字序列不得包含任何千分位符號（例如當小數點為 `,`，千分位為 `.` 時，`0.00001234` 應格式化為 `0,00001234`；而 `12345.00001234` 應格式化為 `12.345,00001234`）。
- **金額輸入框的算式輸入**:
  當使用者在金額輸入框輸入算式（如 `100+50`）時，系統應保留原本的算式輸入支援。如果使用者設定小數點為 `,`，在解析算式（`evaluateExpression`）時，必須先將輸入的 `,` 轉換為 `.` 再進行 eval 計算，計算完成後再格式化為使用者設定的樣式顯示。

## 需求 (Requirements) *(mandatory)*

### 功能需求 (Functional Requirements)

- **FR-001**: 系統必須在 `Extension/popup.html` 的頂部或適當角落新增一個「設定」按鈕（齒輪圖示），其樣式與 hover 效果必須符合既有 `styles.css` 的設計語言。
- **FR-002**: 點擊設定按鈕後，主要換算畫面（包含 `#currency-list`、`#add-currency` 等元素）應被隱藏，並在同一個頁面中以漸變或滑動動畫顯示設定面板（`#settings-panel`）。
- **FR-003**: 設定面板必須包含返回按鈕，點擊後隱藏設定面板，重新顯示主畫面。整個切換過程必須保持在 popup 的寬度（380px）與高度限制（最大 600px）之內。
- **FR-004**: 系統必須提供以下數字格式設定項：
  - **小數點符號 (Decimal Separator)**: 提供單選或下拉選單，選項為 `.` (點) 和 `,` (逗號)。
  - **千分位分隔符 (Thousands Separator)**: 提供單選或下拉選單，選項為 `無` (None)、`空格` (Space)、`.` (點)、`,` (逗號)。
- **FR-005**: 系統必須防止格式衝突。若小數點與千分位設定相同：
  - 當使用者將小數點改為與千分位相同時，千分位自動變更為另一相異值（若改為 `,`，則千分位自動變更為 `.`；若改為 `.`，則千分位自動變更為 `,`）。
  - 當使用者將千分位改為與小數點相同時，小數點自動變更為另一相異值。
- **FR-006**: 設定面板必須提供即時的預覽區塊，以靜態數字 `12345.67` 示範，當使用者在設定面板中切換格式時，預覽結果必須在 100ms 內即時更新。
- **FR-007**: 系統必須提供語言設定下拉選單，選項包括：`English`、`繁體中文`、`簡體中文` 等（可擴充至專案中 translations 字典的所有支援語系）。
- **FR-008**: 語言設定的加載與套用邏輯應與既有的 `getUserLanguage()` 及 `translations` 機制整合。變更後必須立即更新 popup 中的所有 UI 文字，包含主要畫面與設定畫面。
- **FR-009**: 所有設定項目變更時，必須即時寫入 `chrome.storage.sync`。
- **FR-010**: 主要貨幣清單中的金額輸入框在 **非編輯狀態 (Blur)** 下，顯示數值必須套用使用者設定的小數點與千分位格式。
- **FR-011**: 在 **編輯狀態 (Focus/Input)** 下，輸入框內應允許且支援使用者以自訂的小數點符號進行輸入。輸入時，系統需移除非當前小數點的其他千分位符號，並在解析（`parseFormattedNumber`）時將該自訂小數點符號轉換成 `.` 以免破壞 JavaScript 的 `parseFloat`。

### 關鍵實體 (Key Entities)

- **UserSettings (使用者設定資料模型)**:
  - `decimalSeparator` (string): 小數點符號，可選值為 `"."` 或 `","`。預設為 `"."`。
  - `thousandsSeparator` (string): 千分位分隔符，可選值為 `""` (無)、`" "` (空格)、`"."`、`","`。預設為 `","`。
  - `userLanguage` (string): 使用者指定的介面語言代碼，例如 `"en"`、`"zh-TW"`、`"zh-CN"`。預設為 `""`（代表未指定，依瀏覽器語系自動判斷）。

## 成功標準 (Success Criteria) *(mandatory)*

### 可衡量的成果

- **SC-001**: 點擊設定選項後，預覽區塊與主畫面的所有貨幣金額格式應在 **100 毫秒** 內完成即時渲染，無明顯視覺延遲。
- **SC-002**: 重新啟動擴充功能後，讀取並套用儲存的設定（格式與語言）成功率應為 **100%**。
- **SC-003**: 當小數點與千分位設為相異符號時，格式化輸出的數值必須 100% 正確無誤（例如：`12.345,67` 或 `12,345.67`）。
- **SC-004**: 在本功能開發中，**不得引入任何外部重型前端框架**（如 React, Vue, Angular 或 TailwindCSS），且不得請求額外的 Manifest 權限，以維持最小安裝包體積與最高隱私安全性。
- **SC-005**: 既有核心功能（貨幣換算精準度、拖曳排序、新增/刪除貨幣、匯率快取行為）在引入設定功能後應 **0 回歸**，保持 100% 穩定。

## 假設 (Assumptions)

- 使用者環境有正常的 `chrome.storage.sync` API 支援（若因瀏覽器限制 sync 失敗，應能自動降級為 local storage）。
- 主要貨幣金額的內部運算與 API 交互依然統一使用標準 JavaScript 數字（小數點為 `.`，無千分位），只在顯示與輸入解析層進行格式轉換。
- 專案既有的多語系文本字典（`translations`）將擴充以支援設定面板所需的所有文字，並與 `getUserLanguage()` 機制深度整合。
